# (нижче — опис v6.0.0)

## Що змінилось у цій версії

Це повний перепис доставки застосунку (не логіки чи дизайну — той самий
функціонал, той самий вигляд) з однієї монолітної `index.html` (161 КБ, усе
інлайном: Tailwind-CSS, весь JS, уся розмітка) на три окремі, попередньо
мінімізовані файли:

| Файл | Було (інлайн, в одному файлі) | Стало | Gzip |
|---|---|---|---|
| `index.html` | — | 34 КБ | 7,0 КБ |
| `styles.css` | — | 43 КБ | 8,9 КБ |
| `app.js` | — | 50 КБ | 12,7 КБ |
| **Разом** | **161 КБ / 37,2 КБ gzip** | **127 КБ** | **28,7 КБ** |

Це **-21% ваги файлів і -23% трафіку** на кожне завантаження. Але головний
виграш не в цифрах, а в тому, як браузер тепер може вантажити сторінку:

- **Раніше:** браузер мусив повністю завантажити й розпарсити один 161-КБ
  файл, перш ніж хоч щось намалювати — HTML, CSS і JS були одним нерозривним
  блоком.
- **Тепер:** `index.html` (7 КБ) прилітає майже миттєво, а `styles.css` і
  `app.js` вантажаться **паралельно** (сучасні браузери й Vercel вже
  працюють по HTTP/2, паралельні завантаження не заважають одне одному).
- **При повторному візиті:** якщо наступного разу зміниться тільки текст на
  сторінці (`index.html`), браузер і service worker візьмуть `styles.css` і
  `app.js` **з кешу** без жодного мережевого запиту — раніше будь-яка зміна
  в файлі означала повторне завантаження всіх 161 КБ.

### Чому не React/Vue/інший фреймворк

Мені дали повну свободу вибору технологій, і я свідомо лишив ванільний
JavaScript без фреймворку. Для застосунку такого розміру (один список,
кілька модалок, форма) будь-який фреймворк додав би свій рантайм (від ~40 КБ
у React до ~10 КБ у Preact) **плюс** крок збірки (Vite/webpack), який зараз
не потрібен — файли просто лежать у репозиторії й миттєво деплояться на
Vercel без жодної команди `build`. У цих умовах ("швидше і легше, безкоштовний
хостинг на Vercel") ванільний JS — це не компроміс, а найкращий технічний
вибір.

### Як це зроблено безпечно

Розмітку й логіку я **переніс**, а не переписав по пам'яті — це свідомий
вибір, щоб не внести регресій у робочий функціонал без можливості візуально
протестувати результат. Перевірено автоматично:
- синтаксис `app.js` (як мінімізованого, так і читаного) — `node --check`;
- усі 48 викликів `getElementById(...)` звірено з розміткою — жодного
  "осиротілого" ID;
- валідність HTML (`index.html`) — парситься без помилок;
- бекенд (`api/shipments.js`) — синтаксично не змінювався.

Заразом знайшов і виправив реальний (хоч і нешкідливий у браузерах) баг: у
CSS-коментарі був випадковий `*/` всередині тексту (`text-slate-*/bg-slate-*`
без пробілу), який передчасно закривав коментар. Виправлено.

### Структура репозиторію

```
index.html, styles.css, app.js   ← продакшн-файли (мінімізовані, це й деплоїться)
src/                              ← читані вихідники тих самих файлів
  index.html, styles.css, app.js    (редагуйте тут, якщо захочете правити самі;
                                      мінімізовані файли — це їх зібрана версія)
api/shipments.js                  ← бекенд (Vercel Serverless Function)
supabase/schema.sql                ← схема бази
sw.js, manifest.json, icons/       ← PWA
vercel.json                        ← роутинг (оновлено: явно віддає
                                      styles.css/app.js, а не редіректить
                                      їх на index.html, як робив старий конфіг)
```

## Деплой на Vercel (безкоштовно)

1. Заливаєте цей репозиторій на GitHub, підключаєте до Vercel — build-крок
   не потрібен, Vercel просто роздасть файли як static + serverless
   `api/shipments.js`.
2. У Vercel → Settings → Environment Variables додаєте:
   - `SUPABASE_URL`, `SUPABASE_ANON_KEY` — з вашого проєкту Supabase
     (Settings → API). Без них застосунок працює в демо-режимі на
     локальних тестових даних, нічого не ламається.
   - `ADMIN_PASSWORD` — пароль для входу в адмін-частину (за замовчуванням
     `LogisticPro2026!`, якщо не задати свій).
   - `GOOGLE_MAPS_API_KEY` — за бажанням, для точної відстані по дорогах
     (Distance Matrix API). Без ключа застосунок показує наближену оцінку
     по прямій (з `~`).
3. У Supabase виконуєте `supabase/schema.sql` один раз у SQL Editor.

## Попередні зміни (перенесено з версій v5.x)

- Реальна відстань по дорогах через Google Distance Matrix API з кешем у
  `localStorage` і на сервері.
- SVG-спрайт для карткових іконок — кожна картка раніше дублювала ~17
  повних `<path>`-наборів; тепер це короткі `<use href="#i-...">`.
- Лінива підвантаження карт (`IntersectionObserver`) — карта рейсу
  вантажиться, тільки коли картка наближається до екрана.
- Тонування Google-карти під темну тему (invert + hue-rotate), щоб світлі
  плитки не "вибивали" з темного інтерфейсу.
- `env(safe-area-inset-*)` для шапки/навігації/тосту на пристроях із
  чолкою; тач-зони кнопок збільшено до 44×44px на мобільних.
- Кольорова система: окремі токени для світлої й темної теми (синій —
  інтерактивні елементи, троянда/золото/смарагд — статуси заявок), без
  змішування зі стоковими кольорами Tailwind.
- Повний перелік детальніших правок — в історії комітів/попередніх версіях
  README, якщо знадобиться.
